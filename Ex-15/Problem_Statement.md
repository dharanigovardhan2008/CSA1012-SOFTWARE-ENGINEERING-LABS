# Experiment 15 – Work with Git Branches and Resolve Merge Conflicts

## Aim

To understand Git branching strategies and demonstrate how to resolve merge conflicts while collaborating on a shared GitHub repository.

---

## Problem Statement

Git branches enable developers to work on different features independently without affecting the main codebase. During collaboration, multiple developers may modify the same file, resulting in merge conflicts. Git provides mechanisms to identify and resolve these conflicts before integrating changes into the main branch.

Using **Git** and **GitHub**, demonstrate the complete workflow of creating branches, making changes, resolving merge conflicts, and merging the updated code through a Pull Request.

---

## Objectives

- Understand Git branching concepts.
- Create and switch between branches.
- Commit and push changes to GitHub.
- Merge branches and resolve merge conflicts.
- Create and submit a Pull Request.
- Learn collaborative development using Git and GitHub.

---

## Requirements

Perform the following tasks:

1. Clone a shared GitHub repository.
2. Create a new feature branch.
3. Switch to the feature branch.
4. Modify an existing file (such as the README file or source code).
5. Commit the changes with a meaningful commit message.
6. Push the feature branch to GitHub.
7. Pull the latest updates from the main branch.
8. Merge the main branch into the feature branch.
9. Resolve any merge conflicts manually by editing the conflicting files.
10. Mark the conflicts as resolved and commit the merge.
11. Push the updated feature branch to GitHub.
12. Create a Pull Request.
13. Submit a summary describing:
    - Steps performed
    - Merge conflicts encountered
    - Method used to resolve the conflicts

---

## Tools Required

- Git
- GitHub
- Visual Studio Code (or any Git-supported IDE)

---

## Deliverables

- GitHub Repository
- Feature Branch
- Merge Conflict Resolution
- Pull Request
- Pull Request Link
- Summary Report
- Screenshot(s) of the conflict resolution and Pull Request

---

## Expected Outcome

A successful demonstration of Git branching, merge conflict resolution, and collaborative software development using GitHub. The project should include a resolved merge conflict, an updated feature branch, a completed Pull Request, and a summary explaining the collaboration and conflict resolution process.
